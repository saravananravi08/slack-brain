## 2026-08-31 — Implementation

- Added a per-resource observation queue and input processor. Exact channel records are queried only by the pinned channel resource, checked again before observation, and supplied with content-local sender/source attribution without rewriting exact storage.
- Kept built-in turn-driven OM disabled because pinned resource scope does not support async buffering. The standalone supported engine is scheduled without awaiting model work, so exact capture and response setup do not depend on observer availability.
- Added rolling-summary/observation access, category-focused observer/reflection config, content-free lag/failure metrics, and a synchronous DerivedInvalidation sink that queues clear-and-regenerate work.
- Per-channel serialization prevents ordinary consolidation and edit refresh from racing inside this consumer. A failed refresh leaves no knowingly stale observation record and does not alter exact messages.
- Synthetic tests cover two-channel isolation, human/bot/app attribution, detached no-post processing, failure isolation, summary access, and edited-source regeneration.
