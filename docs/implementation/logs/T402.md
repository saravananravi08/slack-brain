- Decisions/assumptions:
  - **Sender attributes are an input, not an inference.** T401 §7.1 measured that a Slack message event carries no external, guest, or deactivated flag, yet `NormalizedEvent` requires the first two and T203's guard requires all three. The only alternative to taking them from the caller is defaulting them to `false`, which would hand the guard a Slack Connect user wearing a full member's clothes. `context.sender_attributes` is therefore required, and its absence returns `{skip:'malformed_event'}` rather than a benign-looking event.
  - **`sender_is_deactivated` is carried on `NormalizedEvent`**, extending slack-event.md §2 by one field. This is the same contract gap T203 recorded from the other side; carrying it here is what lets T405 build an `AuthorizationEvent` from a `NormalizedEvent` with no second lookup. A `pipeline.test.ts` case proves the composition. Still needs the coordinator decision T203 asked for: either slack-event.md gains the field or T004 amends the contract.
  - **`event_id` must be supplied, never fabricated.** The envelope is the only place it exists, and T401 §6 measured that the pinned adapter hands a handler the *inner* event. `normalize` accepts either the full `event_callback` envelope or `context.delivery_event_id`; with neither it skips as `malformed_event`. Deriving a delivery key from the message would collapse the two identities slack-event.md §3 deliberately separates. The failure is loud and uniform on purpose — a mis-wired T405 skips every event visibly rather than running with a silently weakened dedupe. **Integration note for T405:** capture the envelope ID at the adapter boundary and pass it through.
  - **A mutation's `message_ts` is the target message's ts**, not the mutation event's, so `messageKey` addresses the record T404 must update or delete. The mutation event's own ts becomes `edited_at`.
  - **Mutations are delivery-deduped only.** Two genuine edits of one message share a `messageKey` by design; content-deduping them would drop the second edit and leave text the author had already replaced. A replayed mutation is caught by its `event_id` — the only layer doing so, since T401 §6 measured that the SDK deduplicates mutations not at all.
  - **Delivery is claimed before content.** In the other order a retry could claim the content key and make a racing original delivery look like a duplicate record. A recording-ledger test asserts the order and that a duplicate delivery never reaches the content claim.
  - **Classification takes `subscribed_thread` as an input.** slack-event.md §1 requires classification to be a pure function of the event, and T401 §5 found subscription is what turns an ordinary message into addressed traffic. Passing it in keeps the function pure while letting T405 supply the fact.
  - **Mention detection is text-based**, matching the pinned SDK. Slack delivers a channel mention as both `app_mention` and `message`; classifying on event type alone would make whichever copy wins the dedupe race look ambient.
  - **`thread_broadcast`, `file_share`, and `me_message` are content-bearing**, not system noise. Listing them explicitly, with a test, because the failure mode is silent: treating one as a system subtype would drop text a person wrote and nothing downstream would report a gap.
  - **No policy leaks into the normalizer.** `unapproved_*`, `external_user`, and `guest_user` are authorization's (slack-event.md §5); `NormalizerSkipReason` excludes them at the type level, and a test asserts an unapproved channel still normalizes so the guard has something to deny.
  - **Identity keys come from T202's `resource-policy.ts`**, not rebuilt here — a hygiene test asserts the import and that no other module composes a key by hand.
  - **Negatives were mutation-checked.** Removing the mutation guard from `deduplicate` fails exactly the three tests that claim it, so those assertions measure behaviour rather than passing by construction.
  - The hygiene scan strips comments before matching, because a doc comment that names `Date.now()` in order to say the module never calls it would otherwise fail the check it documents.
