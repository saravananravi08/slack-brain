- Result: All verification passed. Implementation commit `2d36a86`. Task marked Ready for Integration.
- Decisions/assumptions:
  - **`bot.onNewMessage(/[\s\S]*/, handler)` is the chosen ambient hook.** It is a documented API of the pinned SDK, fires for ordinary non-mention messages and thread replies, and posts nothing. No polling is added, and no new Slack scope or event subscription is needed — `message.channels` is already in the T003 manifest, and edits and deletes arrive on that same subscription.
  - **Subscription beats pattern matching — the finding P04 must design around.** Once T104 subscribes a thread on first mention, later ordinary messages in that thread reach `onSubscribedMessage` with `isMention === false`, not the ambient handler. T403 must persist from both handlers idempotently, and T405 must settle the INV-6 rule deliberately. Recorded in spike §5.
  - **Mutations are not deduplicated by the SDK.** `handleMessageUpdated`/`handleMessageDeleted` bypass dedupe and lock routing; a replayed delete fires the handler twice (asserted). Idempotency for D005 is entirely T404's.
  - **Two dedupe layers exist for new messages**, both durable through the `StateAdapter`: delivery by `slack:event-delivered:<event_id>` (24 h, consulted only on retries) and content by `dedupe:slack:<ts>` (default 10 min). Neither is a substitute for the durable `messageKey` identity FR-MEM-007 and AC-14 require.
  - **Socket Mode acks before processing**, so handler failure never becomes a Slack retry and at-least-once delivery is handled in state rather than by Slack.
  - **The parsed author carries no external/guest/deactivated flag**, and the adapter's cached user record does not either. T203's `SenderResolver` must make its own `users.info` call and needs the `users:read` scope — which the current credentials lack. Recorded in spike §7.1 and folded into B-01.
  - **Only `isMe` is filtered by the SDK**; other bots and apps reach the handler, so the ambient path needs T104's `isBot`/`isSystem` check repeated.
  - **The spike suite is a version guard, not a unit test.** It runs on every `npm test` against the pinned SDK, so a `chat`/`@chat-adapter/slack` bump that changes routing, dedupe keys, ack ordering, or mutation dispatch fails a named test instead of silently invalidating P04's design. Documented in spike §10.
  - **Negative assertions were mutation-checked.** Feeding a normal user into the self-message case and an empty subtype into the ignored-subtype case both fail the suite, so "no handler fired" is a measurement rather than a race. The harness awaits the real dispatch promises rather than draining a timeout.
- Blockers:
  - **B-01 (open, does not block handoff or T402/T403/T404): live envelope confirmation not performed — the available Slack credentials are not the T003 development app's.** Evidence in the entry above and in spike §8. Owner: Slack workspace operator / coordinator.
