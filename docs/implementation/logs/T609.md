# T609 — Proactive action mode

## Outcome

Implemented D021 for opt-in proactive action on live, unaddressed channel messages.

- Added `GIST_PROACTIVE_CHANNELS` with empty/off default and validated comma-separated channel IDs.
- Added `GIST_PROACTIVE_COOLDOWN_MS` with default `60000`.
- Added a bounded relevance gate using T704 channel context and one deterministic OpenAI JSON-schema classification call.
- Authorized candidates before context retrieval/classification.
- Routed `act=true` through existing `channel.handlers.onNewMention`, preserving thread routing and response behavior.
- Reused delivery dedup and kept mention/edit-trigger paths out of proactive classification.
- Added serialized per-channel in-memory cooldown state.
- Classifier/context failures fail closed and emit only a content-free error class.

Implementation commit: `985bfee` (`feat(T609): proactive action mode per D021`)

## Coordinator/operator ruling

Coordinator approved one additional implementation path in write scope: `src/mastra/index.ts`. This was required because runtime composition owns validated config, authorized request context, T704 `ChannelContextProvider`, and `createLiveSlackChannel` wiring.

Operator required authoritative self-exclusion before classification. The live raw route gates on T603 `NormalizedEvent.sender_class === 'human'`; Gist, Kilo, bot, app, and system senders cannot reach authorization, context retrieval, cooldown evaluation, or the classifier regardless of message text. Tests pin direct Gist traffic, proactive response echo plus replay, bot traffic, and app traffic as captured but never classified or answered.

## Regression coverage

- Relevant unaddressed human root → one response.
- Relevant unaddressed human reply → one in-thread response.
- `act=false` → no response.
- Bot/app/Gist sender → no classification and no generation.
- Proactive Gist response echo/replay → captured, no re-evaluation, no loop.
- Unauthorized candidate → no context/classification.
- Cooldown blocks rapid second action.
- Delivery replay produces no second action.
- Non-proactive channel remains capture-only.
- Classifier failure fails closed with content-free logging.
- Mention traffic bypasses proactive classification.
- Config parsing/defaults and single JSON-schema provider call are pinned.

All identifiers and content in tests are synthetic.
